# Metallic-glass density prediction under composition-family holdout

This repository provides the experimental data, cross-validation predictions, and code used to study density prediction for metallic glasses. The analysis compares ten model configurations on 380 measured densities using both random 10-fold cross-validation and 10-fold validation that holds out entire composition families. The family labels are defined by K-means clustering of elemental fractions into 36 groups.

The archived out-of-fold predictions support the reported model comparisons without retraining. The training scripts are also provided for readers who want to rerun the models.

## Get started

Use Python 3.12 and install the packages in `requirements-main.txt`. From the repository root, run:

```bash
python code/make_figures.py
python code/analyze_predictions.py
python code/make_cv_splits.py
```

`make_figures.py` recreates the six main figures and three supplementary figures from the archived tables in `figure_data/`, saving PDF, SVG, and PNG files in `figures/`. `analyze_predictions.py` calculates pooled MAE, RMSE, R², and prediction–observation slope from the published predictions. It also draws composition families with replacement to estimate confidence intervals; its outputs go to `results/recomputed/`. `make_cv_splits.py` regenerates the outer folds in `results/cv_splits_recomputed.json` for comparison with the archived `data/cv_splits.json`.

The published interval values, including paired random-versus-grouped gaps, are in `results/bootstrap_summary.csv`. The recomputation script generates fresh bootstrap draws, so its interval endpoints may differ slightly.

## Data and results

| File | Description |
| --- | --- |
| `data/experimental_density_380.csv` | Curated experimental densities in g cm⁻³ and 46 normalized elemental-fraction columns named `x_<element>` |
| `data/curation_ledger_417.csv` | Candidate compositions and densities, source compilation, original curation notes, and links to final records where identifiable |
| `data/composition_families_k36.csv` | K-means family labels and two-dimensional coordinates used in the composition-space figure |
| `data/cv_splits.json` | Archived train/test indices for each outer random and grouped fold |
| `results/out_of_fold_predictions.csv` | One held-out prediction per record, model, and protocol: 7,600 rows in total |
| `results/bootstrap_summary.csv` | Cluster-bootstrap summaries for pooled metrics, validation gaps, and prediction–observation slopes |
| `figure_data/` | Numerical inputs for the figures |
| `SOURCE_MANIFEST.json` | File hashes and paths to the inputs from which this release was assembled |

`record_index` is a zero-based identifier shared across the data, family-label, split, and prediction files. In `out_of_fold_predictions.csv`, `fold` identifies the outer test fold, `model_id` identifies the configuration, `cv_protocol` is `random_10fold` or `grouped_10fold`, and both density columns are in g cm⁻³. Each fold in `cv_splits.json` is a pair of `[train_indices, test_indices]`. Neural models additionally use a validation split within the outer training pool for early stopping; those splits are generated by the training scripts.

The 417 candidate records came from Wang, *Progress in Materials Science* **57**, 487–656 (2012), DOI: 10.1016/j.pmatsci.2011.07.001, and Miracle, *Acta Materialia* **61**, 3157–3171 (2013), DOI: 10.1016/j.actamat.2013.02.005. The ledger retains the source workbook's original notes, including notes written in Chinese. Candidate rows 1–217 are from Wang and rows 218–417 from Miracle. `source_order_within_compilation` gives their order in that workbook, not a row number in a publication. Links to final records were reconstructed using workbook order, compositions, and correction notes. Six candidates have no final-record link because they were excluded or a cross-source duplicate link could not be resolved from the workbook. The available provenance identifies the two compilations; it does not identify an individual source study for every record.

## Model identifiers

| `model_id` in the prediction files | Model in the article | ID in figure inputs |
| --- | --- | --- |
| `packing_eta_mae_optimized` | Packing model, MAE-optimized η | `packing_eta_train_mae_opt` |
| `packing_eta_median` | Packing model, median η | `packing_eta_train_median` |
| `roost_rom_feature` | Roost + ROM density feature | `Roost_trunk_mixing_rule` |
| `roost_mass_radius_embedding` | Roost + mass–radius embedding | `Roost_physics_embed` |
| `roost_hs_feature` | Roost + hard-sphere density feature | `Roost_trunk_atoms_density` |
| `roost_mp_pretrained` | Materials Project-pretrained Roost | `Roost_transfer` |
| `rom_density` | Rule-of-mixtures density | `mixing_rule` |
| `rf_mendeleev` | Random Forest, Mendeleev features | `random_forest_mendeleev` |
| `roost_baseline` | Baseline Roost | `Roost_scratch` |
| `rf_magpie` | Random Forest, Magpie features | `random_forest_magpie` |

ROM denotes the additive-volume rule of mixtures. The hard-sphere reference uses elemental masses and Miracle radii. The bootstrap summary uses `random_vs_grouped` for rows describing a difference between protocols.

## Rerun model training

The model implementations are in `code/scripts/`, with shared functions in `code/src/`. The scripts' default parameters contain the reported model settings and seeds. The training scripts read the archived family labels in `data/composition_families_k36.csv` by default. To regenerate clustering diagnostics and then train the models fitted to the experimental data, run:

```bash
python code/scripts/make_composition_families.py
python code/scripts/train_physical_models.py
python code/scripts/train_random_forest.py
python code/scripts/train_roost_baseline.py
python code/scripts/train_roost_physics.py
```

After all model configurations have been run, `assemble_model_matrix.py`, `bootstrap_oof_metrics.py`, `analyze_scale_fidelity.py`, and `analyze_family_residuals.py` produce the downstream analyses from model outputs.

The Magpie Random Forest uses the separate Python 3.11 environment specified in `requirements-magpie.txt`. Run `train_random_forest.py` with `--feature-set magpie` and a distinct output directory, for example:

```bash
python code/scripts/train_random_forest.py --feature-set magpie --output-dir results/phase4_cv_random_forest_magpie
```

The Materials Project-pretrained Roost additionally requires computed-density records and a pretrained checkpoint. `code/scripts/fetch_mp_density.py` retrieves current, non-deprecated records through the Materials Project API using an `MP_API_KEY` environment variable. `code/scripts/pretrain_roost_mp.py` then trains the checkpoint, and `code/scripts/train_roost_transfer.py` fine-tunes it in each experimental training fold. The study used 154,377 computed-density records. A current API download may differ from that historical set. The API export and checkpoints are not included in this repository.

Elemental masses and densities are supplied by Mendeleev; `data/features/` contains the Miracle-radius table and the derived physical embedding used by the physical-input models. Magpie descriptors come from matminer, and baseline Roost uses the MatScholar embedding provided by Aviary.
